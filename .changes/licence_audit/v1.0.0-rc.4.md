## v1.0.0-rc.4 - 2026-11-24

### Added

#### The manifest option accepts directories.

You can pass a directory to `--manifest` with the same project-root and
configuration discovery as a manifest file. Missing manifest errors name
the attempted file and directory and suggest `gleam deps download` or
`--manifest=PATH`.

#### Exceptions can cover invalid licence expressions.

Use `invalid-licence-expression` exceptions for an exact locked Hex
package/version and raw licence label. SPDX allow/deny rules remain strict.
The CLI explains invalid labels without offering them in `update` and
accepts legal CRLF token whitespace.

#### Output and version options have short aliases.

Use `-o PATH` as an alias for `--output` on `sbom` and `notices`, and root
`-V` as an alias for `--version`. Lowercase `-v` remains verbose output.

#### SBOM output supports SPDX 2.3 JSON.

Use `sbom --format=spdx-json` to generate SPDX 2.3 JSON output. CycloneDX
remains the default format.

#### Report and check commands support schema-versioned JSON.

Use `--format=json` with named `report`, `check`, and `vulns` commands for
structured errors, retained partial findings, gate verdicts, and exception
coverage. Text defaults and exit codes remain unchanged.

#### Licence reports show package totals and check verdicts.

Both `report` and `check` show package totals. Licence checks show a passing
verdict or, after failure, a unique package finding list.

#### Explicit policy edits and dry runs do not require a terminal.

Use `update --allow=...`, `update --deny=...`, or both flags to replace
policy lists without a terminal. Use `update --dry-run` to preview without
changing the policy file. These flags skip the interactive picker; `update`
without any of them requires an interactive terminal.

Omitted lists are preserved, empty values clear lists, and uncovered
licences are reported without failing the update.


### Changed

#### Metadata and advisory requests use four workers.

The CLI fetches package metadata and OSV advisory details with four workers
while preserving report and warning order. Each command shares connection
fallback, host cutoffs, and rate-limit deadlines. Interrupted or unconfirmed
HTTP work is reported as incomplete with exit code `2`.


### Fixed

#### Licence-only checks accept the American spelling.

Use `check --checks=licenses` as an alias of `--checks=licences`. Both
spellings use the same licence-only validation.

#### Cache refresh failures produce a warning.

The CLI warns when it cannot replace a stale cache entry. The current
command still uses the fresh fetched result.

#### Local SBOM components include repository references.

Local SBOM components with declared GitLab, Bitbucket, or SourceHut
repositories include `vcs` references. Publication identities remain
unchanged.

#### The shipped executable excludes test helpers.

Test-only Erlang helpers are no longer included in the shipped executable.

#### Incomplete vulnerability checks retain available findings.

Both `check --checks=vulns` and `check --checks=all` keep available advisory
findings and reviewed exception coverage when other advisory details cannot
be fetched. Incomplete checks still exit `2`.

#### CLI usage errors stay within three lines.

Usage errors use at most three stderr lines and include a command-specific
help pointer. The CLI names unknown commands even with `--help`, reports
clear parser causes, and shows migration hints for removed flags.

#### Help output respects the destination color policy.

Help output honors `--color`/`--colour` and the color policy of its stdout
or stderr destination.

#### Notice lookups refresh licence text after tag changes.

The `notices` command expires tag lookups after 24 hours and revalidates
repository fallback before reusing final materials. Moved tags cannot
retain stale licence text.

#### Policy updates preserve temporary paths reused by other writers.

After a successful policy replacement, `licence_audit update` no longer
deletes a temporary pathname that another writer has reused.

#### Production reports retain the full dependency chain.

Both `report --scope=prod` and `check --scope=prod` keep the full production
dependency chain when a shorter development path reaches the same package.

#### Picker-driven updates require an interactive terminal.

When none of `--allow`, `--deny`, or `--dry-run` is supplied, `update` uses
the interactive picker and requires a terminal on both stdin and stdout.
If either stream lacks a terminal, the CLI prints one diagnostic and exits
`2` before reading policy or manifest files, opening caches, or fetching
metadata.

#### Hex and OSV requests retry transient failures within limits.

The CLI retries transient Hex API and OSV failures within service attempt
limits and a 30-second retry-wait budget. It stops unavailable hosts after
three exhausted timeout/connect operations and splits OSV batches into at
most 1,000 queries without partial coverage.

#### CLI help shows meaningful flag values and command summaries.

Help output shows meaningful flag values and one-line command summaries.
Command descriptions and Boolean value parsing remain unchanged.

#### The update picker stops reading before cleanup.

The `update` picker stops its keyboard reader before restoring the terminal
or writing policy.

#### Successful IPv4 archive downloads omit IPv6 no-address warnings.

The CLI suppresses IPv6 no-address warnings when source archive downloads
succeed over IPv4.


### Dependencies

#### Source archive downloads use Gluegun 1.1.0 connection cleanup.

Upgrade Gluegun from 1.0.0 to 1.1.0 so failed or timed-out source archive
downloads attempt bounded supervisor shutdown before forced termination.
Existing download limits, deadlines, flow control, and connection ownership
remain unchanged.
